# v0.3 Target Ontology · 修订稿

**状态**：draft  
**日期**：2026-05-18  
**定位**：本文件定义 v0.3 阶段的目标图谱 ontology。它是最终入图目标，而不是 Codex 直接输出的抽取 schema。

---

## 1. 设计结论

当前推荐采用“目标 ontology + 抽取投影视图 + 后处理归一”三层结构：

1. **目标 ontology**
   表达最终希望沉淀在图谱中的业务世界。
2. **抽取投影视图**
   只保留报告文本中能稳定抽到的部分，供 Codex skill 使用。
3. **后处理归一层**
   负责 business key 生成、关系方向收敛、名称对齐、时间标准化和派生关系补全。

本文件只讨论第一层。

---

## 2. 建模原则

### 2.1 型号、实例、设计件、实物件必须分层

- `ProductModel`：型号层
- `ProductInstance`：整机实例层
- `BOMPart`：设计件层
- `PartSerial`：实物序列件层

这是 v0.3 ontology 的核心约束，不再回退为单一 `Part` 模型。

### 2.2 事件、报告、原因、措施必须分层

- `ProductEvent`：现实世界发生的一次事件
- `EightDReport`：围绕事件生成的治理/分析报告
- `CauseItem`：报告中的原因项
- `ActionItem`：报告中的措施项

图谱必须允许一个事件对应一份或多份分析对象，也允许报告持续演化。

### 2.3 只保留规范方向的关系

目标 ontology 中应定义**唯一 canonical direction**。  
反向遍历由图数据库查询承担，不在 ontology 里重复定义成对关系。

### 2.4 行为主体采用 Person / Organization 双轨建模

凡是可能出现“人名 / 公司名 / 部门名 / 客户名 / 供应商名”混用的字段，统一采用：

- 原始字符串字段保留
- `Person` / `Organization` 关系在高置信时建立
- 不确定时只保留原始字符串，不强行建实体

### 2.5 原始文本属性与归一关系并存

如：

- `manufacturerName` 是原始文本属性
- `manufacturer -> Organization` 是归一后的实体关系

这类“原始值 + 对齐实体”双轨模式在 v0.3 中是允许且推荐的。

### 2.6 时间语义必须显式化

v0.3 起不再把关键业务时间继续视为普通文本。  
至少区分：

- 业务发生时间
- 安装/拆卸时间
- 报告时间
- 系统写入时间

### 2.7 规范时间字段与原始时间文本双轨保留

为兼顾后续时序查询和当前报告里的非标准时间表达，关键时间属性建议采用：

- 规范化时间字段，如 `reportDate` / `occurredAt`
- 原始时间文本辅助字段，如 `reportDateRaw` / `occurredAtRaw`

原则：

- 能高置信标准化时，优先写规范时间字段
- 精度不足时保留原始文本，不强猜具体时刻
- 后续 temporal KG 升级时，以规范字段为主、原始字段为补充证据

## 3. 核心实体层

### 3.1 Core Stable Layer

这是 v0.3 应冻结的核心实体子集：

- `ProductModel`
- `ProductInstance`
- `BOMPart`
- `PartSerial`
- `ProductEvent`
- `EightDReport`
- `CauseItem`
- `ActionItem`
- `FailureMode`
- `Person`
- `Organization`

### 3.2 Temporal / History Layer

这部分属于 v0.3 的增强重点：

- `Installation`
- `CauseItem -> LEADS_TO -> CauseItem`
- 关系级 `valid_from / valid_to / confirmed_at`

### 3.3 Taxonomy / Concept Layer

这部分保留，但优先级低于前两层：

- `EventCategory`
- 产品线/产品族等更泛的分类体系

## 4. 实体定义修订建议

以下不是重写 ontology，而是在既有设计上做稳定性增强。

### 4.1 ProductModel

保留：

- `productLine`
- `productFamily`
- `modelCode`
- `productCategory`
- `manufacturerName`

建议：

- `modelCode` 继续作为主业务键
- `manufacturerName` 保留为原始属性
- `manufacturer -> Organization` 作为归一关系

### 4.2 ProductInstance

保留：

- `serialNumber`
- `assetCode`
- `commissionDate`
- `status`
- `ownerName`
- `siteCity`
- `siteCountry`
- `siteCode`

建议：

- `serialNumber` 作为主业务键
- `commissionDate` 改为 `date/datetime`
- `commissionDateRaw` 作为原始时间文本辅助字段预留
- `ownerName` 保留原始属性
- `ownedBy -> Organization` 作为归一关系

### 4.3 BOMPart

保留：

- `partType`
- `partNo`
- `positionCode`
- `bomLevel`

建议：

- `partNo` 作为主业务键
- 只保留一个层级方向关系，不再同时维护 `parentPart` 与 `childPart`

### 4.4 PartSerial

保留：

- `batchNo`
- `serialNumber`
- `supplierName`
- `status`

建议：

- 主业务键推荐在后处理层生成 `uniqueKey = serialNumber::batchNo`
- `supplierName` 保留原始属性
- `suppliedBy -> Organization` 作为归一关系
- `instanceOfPart -> BOMPart` 保留

### 4.5 Installation

保留：

- `installationId`
- `positionCode`
- `installTime`
- `removeTime`
- `isCurrent`
- `operatorName`

建议：

- `installTime` / `removeTime` 改为 `datetime`
- `isCurrent` 改为 `bool`
- 从语义上视为“带时序语义的记录实体”
- `installTimeRaw` / `removeTimeRaw` 作为原始时间文本辅助字段预留
- `operatorName` 继续保留为原始文本
- `operatedByPerson -> Person` 仅在能确认是个人时建立

### 4.6 ProductEvent

保留：

- `eventId`
- `eventCode`
- `eventType`
- `severity`
- `symptom`
- `status`
- `reporterName`

强制修订：

- `eventTime` 改名为 `occurredAt`
- `occurredAt` 改为 `datetime`
- `occurredAtRaw` 作为原始时间文本辅助字段预留
- `reporterName` 保留原始文本
- 新增：
  - `reportedByPerson -> Person`
  - `reportedByOrg -> Organization`

### 4.7 EightDReport

保留：

- `reportNo`
- `issueTitle`
- `reportStatus`
- `d2ProblemStatement`
- `d4RootCauseSummary`
- `d5PermanentCorrectionSummary`
- `d7PreventionSummary`
- `ownerName`
- `ownerRole`

建议补充：

- `reportDate: datetime | date`
- `reportDateRaw` 作为原始时间文本辅助字段预留
- `ownerName` 保留原始文本
- `ownedByPerson -> Person`
- `responsibleOrg -> Organization`

### 4.8 CauseItem

保留：

- `causeId`
- `title`
- `causeType`
- `isVerified`
- `evidence`

强制修订：

- `isVerified` 改为 `bool`
- 新增 `leadsTo -> CauseItem`

### 4.9 ActionItem

保留：

- `actionId`
- `title`
- `actionType`
- `status`
- `ownerName`

建议补充：

- `dueDate: datetime | date`
- `dueDateRaw` 作为原始时间文本辅助字段预留
- `ownerName` 保留原始文本
- `ownedByPerson -> Person`
- `responsibleOrg -> Organization`

### 4.10 FailureMode

当前仅有 `modeCode` 不足。建议补充：

- `modeName`
- 如有需要再补 `modeCategory`

### 4.11 Person

建议至少保留：

- `personName`
- `title`
- `email`
- `phone`

建议：

- `personName` 作为展示名
- 如果缺少稳定编码，业务键由后处理基于 `personName + org context` 保守生成
- `Person -> BELONGS_TO_ORG -> Organization` 仅在归属明确时建立

### 4.12 EventCategory

当前建议保留：

- `categoryCode`
- 新增 `categoryName`

但不建议把它作为 v0.3 第一阶段核心抽取实体。

### 4.13 Organization

建议至少保留：

- `orgCode`
- `orgName`
- `orgType`

## 5. 规范关系方向

以下关系建议作为 v0.3 canonical direction：

- `ProductInstance -> BASED_ON_MODEL -> ProductModel`
- `ProductModel -> HAS_BOM_PART -> BOMPart`
- `ProductModel -> HAS_BOM_ROOT -> BOMPart`
- `BOMPart -> PARENT_PART -> BOMPart`
- `PartSerial -> INSTANCE_OF_PART -> BOMPart`
- `PartSerial -> INSTALLED_ON -> ProductInstance`
- `PartSerial -> SUPPLIED_BY -> Organization`
- `ProductEvent -> REPORTED_BY_PERSON -> Person`
- `ProductEvent -> REPORTED_BY_ORG -> Organization`
- `ProductEvent -> HAPPENED_ON -> ProductInstance`
- `ProductEvent -> RELATED_SERIAL -> PartSerial`
- `ProductEvent -> RELATED_PART -> BOMPart`
- `ProductEvent -> RELATED_FAILURE_MODE -> FailureMode`
- `ProductEvent -> RESPONSIBLE_ORG -> Organization`
- `ProductEvent -> HAS_8D_REPORT -> EightDReport`
- `EightDReport -> OWNED_BY_PERSON -> Person`
- `EightDReport -> SOURCE_EVENT -> ProductEvent`
- `EightDReport -> AFFECTED_PRODUCT -> ProductInstance`
- `EightDReport -> AFFECTED_SERIAL -> PartSerial`
- `EightDReport -> AFFECTED_PART -> BOMPart`
- `EightDReport -> ROOT_CAUSE -> CauseItem`
- `EightDReport -> CORRECTIVE_ACTION -> ActionItem`
- `EightDReport -> PREVENTIVE_ACTION -> ActionItem`
- `EightDReport -> RESPONSIBLE_ORG -> Organization`
- `CauseItem -> RELATED_FAILURE_MODE -> FailureMode`
- `CauseItem -> RELATED_PART -> BOMPart`
- `CauseItem -> RELATED_SERIAL -> PartSerial`
- `CauseItem -> RELATED_EVENT -> ProductEvent`
- `CauseItem -> BELONGS_TO_REPORT -> EightDReport`
- `CauseItem -> LEADS_TO -> CauseItem`
- `ActionItem -> BELONGS_TO_REPORT -> EightDReport`
- `ActionItem -> OWNED_BY_PERSON -> Person`
- `ActionItem -> VERIFIES_CAUSE -> CauseItem`
- `ActionItem -> RELATED_EVENT -> ProductEvent`
- `ActionItem -> TARGET_SERIAL -> PartSerial`
- `ActionItem -> TARGET_PRODUCT -> ProductInstance`
- `ActionItem -> TARGET_PART -> BOMPart`
- `ActionItem -> RESPONSIBLE_ORG -> Organization`
- `Installation -> OPERATED_BY_PERSON -> Person`
- `Installation -> PRODUCT -> ProductInstance`
- `Installation -> PART_SERIAL -> PartSerial`
- `Installation -> BOM_PART -> BOMPart`
- `Installation -> GENERATED_BY_EVENT -> ProductEvent`
- `Person -> BELONGS_TO_ORG -> Organization`
- `EventCategory -> PARENT_CATEGORY -> EventCategory`

说明：

- 某些领域上看似成对关系，如 `sourceEvent` 与 `has8DReport`，允许在 ontology 层保留双向语义，但实现层必须明确哪一条是写入 canonical edge，哪一条只是查询语义别名。
- 若希望实现层更简单，推荐统一只落 `ProductEvent -> HAS_8D_REPORT -> EightDReport`，其余由查询层反向遍历。

## 6. 派生关系与非直接抽取关系

以下关系或属性更适合由后处理/推理层生成，而不是由 Codex 直接抽取：

- `ProductModel.hasInstance`
- `ProductInstance.hasCurrentPart`
- `BOMPart.childPart`
- `BOMPart.fulfilledBy`
- `PartSerial.replacedBy`
- `Installation.isCurrent` 的最终判定
- `Person -> BELONGS_TO_ORG -> Organization` 的弱归属推断

原则：

- 抽取器输出“文本明确出现且上下文可证实”的事实
- 推理层补“由多个事实综合计算出的当前状态/反向关系/派生关系”

---

## 7. v0.3 Freeze 范围

进入 skill 共创前，建议先冻结以下内容：

1. 核心实体子集
2. 关键时间字段类型
3. 规范时间字段 + raw 时间文本双轨模式
4. `CauseItem -> LEADS_TO -> CauseItem`
5. 规范关系方向
6. Person / Organization 双轨 actor typing 原则
7. 原始文本属性与归一关系并存原则
8. 关系级时间语义与“当前状态由历史推导”的原则

只要这几项先冻结，后续抽取 skill、后处理和 writer 设计都会稳定很多。
